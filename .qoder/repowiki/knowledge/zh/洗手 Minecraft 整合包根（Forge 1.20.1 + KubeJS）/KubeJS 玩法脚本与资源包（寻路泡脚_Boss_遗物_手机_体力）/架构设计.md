模块遵循 KubeJS 标准目录分层，按生命周期与运行端严格切分：
- `startup_scripts/`：游戏启动时一次性注册 Registry 对象（Item/Block/Fluid/Boss/Relic/Oil），由 `boss/bossRegister.js`、`relic/relicRegister.js`、`oil/oilRegister.js` 等提供 Builder DSL，具体实体在 `boss_*.js`、`relic/stage*/xxx.js`、`oilItem/*.js` 中以链式调用声明。
- `server_scripts/`：服务端运行时逻辑，按子系统分目录——`pathfinder/pfMain.js` 暴露 `global.pathfinderTick` 作为每 tick 主循环，内部通过 `pfMovement/pfEntityData/pfSoakManager/pfSleepManager/pfShopManager/pfPathfinding` 等模块协作；`recipes/` 定义各类合成配方；`stamina/`、`phone/`、`backpack/`、`sound/`、`item/`、`serve/` 为独立子系统。
- `client_scripts/`：客户端侧 UI 与 Tooltip，`ui/` 下使用 ApricityUI (`com.sighs.apricityui.WorldWindow`) 渲染 HTML 模板（`assets/kubejs/apricity/footui.html`），`tooltip/` 扩展物品提示。
- `assets/`：客户端资源，除 `kubejs/` 自托管纹理/模型/声音外，大量 `*/lang/zh_cn.json` 覆盖第三方 Mod 文本，另有 `skyfootspa/`、`marguerite/` 等完整子资源包。
- `data/`：服务器端数据（NBT 结构体、Forge tags、FTB Quests、Margarite 对话/主题/维度/结构）。`config/` 存放 KubeJS 配置，`probe/` 缓存 ProbeJS 类型文档供 IDE 补全。
依赖方向单向：client → server（仅通过 NBT/网络同步），startup → server（Registry 完成后被 runtime 消费），各子系统通过 `global.*` 命名空间共享状态（如 `global.pfFootUiClientState`、`global.bossRegister`）。
